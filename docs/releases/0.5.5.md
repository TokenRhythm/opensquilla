# OpenSquilla 0.5.5

## Overview

OpenSquilla 0.5.5 is a feature and maintenance release for the 0.5 stable
line. It brings C5 multi-model fusion, more reliable chats and long-running
tasks, persistent task workspaces, richer document previews, Tencent SkillHub,
and signed Windows installers. It also improves model configuration, Skills,
managed execution, and Desktop startup and recovery.

Existing configuration, chats, Agents, memory, and scheduled jobs stay in the
active profile. Supported database migrations run automatically; no manual
data transfer is required. Quit the running Desktop app or gateway, install
0.5.5 over the current installation, and restart OpenSquilla.

## ✨ What's Improved

### C5 multi-model fusion

The default OpenRouter and TokenRhythm fusion profiles now use the C5 lineup:
four models draft independent candidates, then a tool-capable model combines
them into the answer.

- The candidate models are DeepSeek V4.1 Flash, GLM-5.3 Flash, Qwen3.8 Flash,
  and Qwen3.8 Max. DeepSeek V4.1 Flash handles aggregation; provider-specific
  model IDs are selected by the profile.
- All members use high thinking. Candidate models focus on drafting, while
  the aggregator retains tools and can proceed when at least one candidate
  succeeds.
- Image inputs, physical model labels, usage accounting, and fallback recovery
  remain consistent across the selected routing strategy.

In the reported 100-task DRACO evaluation, C5 improved average quality by
8.45%, reduced average generation cost by 67.59%, and reduced median runtime
by 53.75% against the previous lineup. These are observed benchmark results;
individual workloads vary. See the
[C5 evaluation summary](https://github.com/TokenRhythm/opensquilla/blob/v0.5.5/docs/features/MULTI-MODEL-FUSION-C5-RELEASE-NOTE.md).

### Chats, Plans, and Goals

- Chats recover more consistently after reconnects, sleep, refreshes, and
  window switches. Unsent text and attachment drafts, pending questions,
  routing cards, and task progress retain their correct conversation.
- Plans can investigate with ordinary tools, preserve proposal history, and
  be hidden or restored. Accepted plans run through the shared task runtime,
  with adjustable progress and normal cancellation controls.
- Goals keep natural create, edit, pause, and resume controls. Questions and
  approvals wait within the same task, and usage includes child work and late
  results. Automatic continuation requires a live authenticated client
  subscribed to the session; a Gateway restart requires explicit resume.
- Long conversations use the called model's capacity for compaction and
  attachment admission. Incomplete summaries no longer replace history, and
  image and reasoning context survive more recovery paths.

### Workspace files, documents, and previews

- New ordinary tasks can retain their own workspace. Local HTML previews,
  annotations, saved versions, attachments, and cleanup share that workspace.
- Files referenced in replies can open or download directly. Text previews
  offer line numbers, search, line jumps, refresh, and copying; local Desktop
  connections also support opening files and revealing them in the file manager.
- Document tools read bounded page, slide, paragraph, and sheet ranges.
  Uploaded originals stay intact while supported edits use persistent working
  copies. Image and SVG copying and embedded PDF previews are more reliable.
- Search evidence previews recover truncated web content more consistently,
  and trusted session references provide safer navigation back to related work.

### Model routing and provider setup

- Model settings expose context and output limits, including editable limits
  for custom models. The same limits govern Direct, Router, Ensemble, and
  fallback requests.
- Router presets follow the primary provider, retain custom choices, and
  support provider-specific resets. Model selection and fallback labels are
  easier to read across chat and settings.
- Provider reachability and model verification are separate checks. DeepSeek
  model discovery, native reasoning replay, session naming, and custom
  OpenAI-compatible request bodies are improved.

### Skills and managed execution

- Tencent SkillHub joins the Community Skill sources in the Web UI, CLI, and
  Agent tools. Registry browsing, slash Skill selection, installation progress,
  cancellation, and result details are more consistent.
- The bundled catalog is smaller, and tools are discovered as needed. Existing
  personal and project Skills remain available.
- Managed commands support interactive terminal input and background
  processes. Recommended installations and Desktop packages include platform
  PTY support, with clearer terminal state and process cleanup.
- Supported managed sandboxes can author channel documents through generic
  tools and Skills, with delivery tied to the originating conversation.
  Ordinary channel authoring is unavailable on Windows.

### Desktop and platform reliability

- Desktop opens before model setup completes. Gateway startup, sleep/wake
  recovery, clean-exit restart, Windows Safe mode, and shared storage recovery
  are more reliable.
- Windows installers are Authenticode signed. Verified installer handoff and
  cached download recovery improve the update workflow.
- Sidebar navigation, long lists, narrow composers, task dragging, and
  localized error messages are more consistent. One-shot schedules retain
  concurrent edits and reject already-expired new times.
- Diagnostic bundles better redact sensitive content. Anonymous stability
  telemetry honors the existing privacy controls.

## Upgrading from 0.5.4

Quit the running Desktop app and gateway before upgrading. Back up the active
profile first if you may need to recover or roll back, then install 0.5.5
directly over the existing installation. Supported database migrations run
automatically when the Gateway starts. Unsupported legacy databases are
preserved and reported rather than silently replaced.

- Goal Token budgets and foreground/background execution settings are retired.
  Existing history and usage totals remain readable. Resume paused Goals
  explicitly; automatic continuation now needs a connected, subscribed client.
  Scheduled automations keep their separate execution policy.
- Redundant bundled Skills and the format-specific `create_csv`, `create_xlsx`,
  `create_pptx`, and `create_pdf_report` tools are retired. Update custom Meta
  workflows that refer to retired entries to use current Skills and generic
  tools. Personal and project Skill files are not removed.
- Workspace `BOOTSTRAP.md`, `HEARTBEAT.md`, and `TOOLS.md` integration and
  legacy memory flush/repair pipelines are retired. Existing files remain in
  place; move instructions still needed at runtime into `AGENTS.md`.
- Optional Runtime Packs remain managed through Sandbox settings. Users
  upgrading from 0.5.3 or earlier should install the Python, Node.js, or Git
  Bash packs they need; old bundled developer runtimes are not copied forward.
- Upgrade the Gateway and its clients together to use the current Plan, Goal,
  and workspace features. Desktop and terminal installations keep separate
  profiles; use the explicit transfer controls when moving between them.

> [!IMPORTANT]
> On Windows, users coming from RC3 or an older pre-Preview-4 build must not
> uninstall that build first: older uninstallers may delete
> `%APPDATA%\OpenSquilla`. Back up that directory, then install 0.5.5 directly
> over the existing installation. RC4 and later installers preserve profile
> data during a normal uninstall.

On macOS, drag the new app into Applications, eject the DMG, and open the
Applications copy.

CLI users can reinstall the published wheel over the current tool environment:

```sh
uv tool install --python 3.12 --force --reinstall-package opensquilla \
  "opensquilla[recommended] @ https://github.com/TokenRhythm/opensquilla/releases/download/v0.5.5/opensquilla-0.5.5-py3-none-any.whl"
```

Published wheels, Desktop installers, and container images include the Web UI.
Source builds require Node.js 22.12+ and npm; run `npm ci && npm run build` in
`opensquilla-webui` before building a wheel. See the
[quickstart](https://github.com/TokenRhythm/opensquilla/blob/v0.5.5/docs/quickstart.md).

Non-user-initiated network observability can be disabled before startup with
`OPENSQUILLA_PRIVACY_DISABLE_NETWORK_OBSERVABILITY=true` or:

```toml
[privacy]
disable_network_observability = true
```

The compatibility variables `OPENSQUILLA_TELEMETRY_DISABLED=true` and
`OPENSQUILLA_UPDATE_CHECK_DISABLED=true` remain honored.
