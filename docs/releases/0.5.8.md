# OpenSquilla 0.5.8

## Overview

TokenRhythm account sign-in in Desktop, task-aware local model routing, and
model recommendations you can review and apply without waiting for an app update.

## ✨ What's Improved

### TokenRhythm account in Desktop

Sign in to TokenRhythm from Desktop to connect your account to OpenSquilla.

- View your account balance, open recharge, and check today's local token usage
  from the sidebar account menu.
- Use account credentials for supported text, image, and video models.
- An explicit sign-in can make TokenRhythm your primary model connection;
  manual provider setup and switching remain available in Settings.

Account sign-in requires Desktop. The token summary reflects this local
Gateway's usage, rather than your account's complete billing history.

### SquillaRouter follows the task

The new local router combines BERT-60M INT8 task-intent classification with
LightGBM model-tier selection.

- **New Task** selects a tier from the current request.
- **Continue** keeps the current task's tier.
- **Redo** advances one tier, up to C3.

Routing stays local, and image conversations can use a configured tier with
vision support. See the upgrade notes below for the changed routing defaults.

### Review and adopt model recommendations

OpenRouter and TokenRhythm recommendations refresh at Gateway startup and
every 24 hours. Preview the proposed Router or Ensemble models and confirm
before applying them; downloading a recommendation never replaces saved
models automatically. Cached recommendations remain available offline, and
background checks honor your privacy settings.

New chats also remember the last manually selected mode and model, while CLI
tables adapt to terminal width. This release improves long-session history,
attachment editing, provider streaming, and Desktop shutdown reliability.

See the [full changelog](https://github.com/TokenRhythm/opensquilla/blob/v0.5.8/CHANGELOG.md#058---2026-11-05).

## Upgrading from 0.5.7

Quit Desktop and the Gateway, back up the active profile, and install over the
existing installation. Configuration, chats, Agents, memory, and schedules stay
in that profile; no manual data transfer is required. Supported database migrations
run automatically. Upgrade clients and Gateway together.

**Review your router configuration:** saved `strategy = "v4_phase3"` settings
now select `lightgbm_model`. An explicitly disabled router stays disabled.
The new policy uses one model per tier and does not enter C3 Ensemble; direct
and explicit Ensemble modes keep their own configuration. Existing router budget
caps no longer lower the initial tier, although quality retries still check the
budget. To retain the previous routing behavior, explicitly set:

```toml
[squilla_router]
strategy = "legacy_v4_phase3"
```

If `squilla_router.lightgbm_model_dir` points to the old model bundle, remove
that override to use the packaged models or replace the entire external bundle
with the current one. See the [router migration guide](https://github.com/TokenRhythm/opensquilla/blob/v0.5.8/docs/features/squilla-router.md#upgrading-to-the-model-policy).

Supported Windows and macOS Desktop builds download available updates in the
background; installation requires your confirmation.

<details>
<summary>Upgrading from 0.5.5 or earlier</summary>

- The background-music player and experimental router self-learning were
  retired in 0.5.6. Personal music and historical training files remain on disk.
- Goal Token budgets and foreground/background execution settings are retired.
  History and usage remain; explicitly resume Goals after a Gateway restart.
- Retired bundled Skills and format-specific authoring tools should be replaced
  with current Skills and generic tools. Ordinary channel authoring is unavailable on Windows.
- Workspace `BOOTSTRAP.md`, `HEARTBEAT.md`, and `TOOLS.md` integration is retired.
  Files remain; move required instructions into `AGENTS.md`. From 0.5.3 or earlier,
  reinstall needed optional Runtime Packs through Sandbox settings.

> [!IMPORTANT]
> Windows users coming from RC3 or an older pre-Preview-4 build must not
> uninstall that build first: older uninstallers may delete
> `%APPDATA%\OpenSquilla`. Back it up, then install 0.5.8 in place.

</details>

On macOS, replace the app in Applications, eject the DMG, and open that copy.
Published artifacts include the Web UI; source builds require Node.js 22.12+.

<details>
<summary>Privacy controls and notices</summary>

Disable automatic network observability with
`OPENSQUILLA_PRIVACY_DISABLE_NETWORK_OBSERVABILITY=true` or
`[privacy]` → `disable_network_observability = true` in TOML.
`OPENSQUILLA_TELEMETRY_DISABLED=true` and
`OPENSQUILLA_UPDATE_CHECK_DISABLED=true` remain honored.
See [Privacy](https://github.com/TokenRhythm/opensquilla/blob/v0.5.8/PRIVACY.md)
and [Third-party notices](https://github.com/TokenRhythm/opensquilla/blob/v0.5.8/THIRD_PARTY_NOTICES.md).

</details>
