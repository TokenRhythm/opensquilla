# OpenSquilla 项目工作区设计

## 目标

OpenSquilla 同时支持两种任务：

1. 普通任务：用户没有选择项目，继续使用 OpenSquilla 现有默认工作区。
2. 项目任务：用户主动选择一个项目目录，该目录成为对应任务的工作区。

项目工作区独立于任务存在。用户选择项目后，它必须立即出现在侧栏；即使尚未发送消息，也显示项目和“无任务”状态。

## 已确认的用户体验

### 默认主界面

- 启动后默认不选中任何项目。
- 用户可以像现在一样直接创建普通任务。
- 普通任务继续使用 OpenSquilla 默认工作区。
- 普通任务不显示“默认工作区”标题，平铺在侧栏底部。

### 选择项目

- 用户可以从主界面输入区附近或侧栏项目区选择任意已有目录。
- 目录通过验证与信任确认后，立即保存为项目工作区。
- 项目立即显示在侧栏项目区域；新项目放在未置顶项目的最上方。
- 主界面立即进入该项目下的空白新任务。
- 输入区域明确显示当前项目名称和路径，避免用户误判执行位置。
- 项目标识旁提供轻量关闭按钮；关闭只退出项目草稿并返回默认工作区，不移除项目。
- 在用户发送第一条消息前，不创建正式任务记录。

### 发送第一条消息

- 第一条消息发送时，正式创建任务，并一次性绑定到当前项目工作区。
- 任务创建、首条消息和工作区绑定必须作为同一次操作完成。
- 如果操作失败，不留下空任务或绑定错误的任务。
- 项目原来的“无任务”状态被新任务替换。

### 侧栏结构

侧栏从上到下显示：

```text
项目 A
  项目任务 1
  项目任务 2

项目 B
  无任务

普通任务 1
普通任务 2
```

- 项目工作区始终位于普通任务上方。
- 项目位置不随任务活跃度变化；未置顶项目按添加顺序固定，新项目位于未置顶区域最上方。
- 置顶项目显示在独立的置顶区域；新置顶项目位于置顶区域最上方，之后不随任务活跃度移动。取消置顶后，项目回到未置顶区域最上方。
- 点击项目名称只展开或收起任务列表，绝不切换主界面或当前工作区。
- 只有点击具体任务才切换到对应任务和项目工作区。
- 项目名称左侧始终显示项目信息图标；悬停或键盘聚焦时显示完整路径和顶层任务数量。
- 项目行右侧依次放置笔形“新建任务”按钮和“更多”按钮；两者默认完全隐藏，只在项目行悬停或键盘聚焦时显示。
- 笔形按钮创建绑定到该项目的空白任务草稿，并使用与现有侧栏一致的线条、尺寸和颜色。
- 全局“新建任务”始终返回默认工作区，创建普通任务草稿。
- 项目下没有任务时显示“无任务”。
- 项目内部任务和底部普通任务都按最近活动时间排序，但任务活动不能改变项目位置。

### 项目更多菜单

项目“更多”菜单包含：

- 置顶项目；已置顶时显示取消置顶。
- 编辑项目：打开小型弹窗，只允许修改项目显示名称；项目路径只读。
- 删除项目任务历史：二次确认后永久删除该项目下的全部任务和子任务，保留项目记录和磁盘文件。确认界面显示待删除任务数量。
- 移除项目：只从项目列表隐藏项目，保留任务历史和磁盘文件；以后重新选择同一路径时恢复项目及历史。

## 数据与职责

### 项目工作区

项目工作区是独立保存的对象，至少包含：

- 稳定标识
- 规范化后的项目目录
- 用于侧栏显示的名称；允许用户自定义
- 固定排序信息和置顶状态
- 是否已从项目列表移除
- 信任状态

同一个规范化目录只能对应一个项目工作区。Windows 路径的大小写、斜杠、UNC 和目录链接不能制造重复项目。

任何有效文件夹都可以作为项目，不要求它是 Git 仓库。如果检测到 Git 信息，可以作为附加信息展示，但不能成为项目使用门槛。

### 任务

- 项目任务保存所属项目工作区的稳定标识。
- 普通任务没有项目工作区标识，运行时使用默认工作区。
- 恢复任务时使用任务原来绑定的项目，不能被当前界面选择覆盖。
- 从项目任务创建分支时继承原项目。
- 第一版不允许在已有任务中途切换主项目；需要换项目时创建新任务。
- 项目信息中的任务数量只统计顶层任务，不重复计算子任务。

### 最终有效工作区

后端是工作区状态的唯一权威来源：

- 项目任务使用项目目录。
- 普通任务使用 OpenSquilla 默认工作区。
- 界面展示、终端命令、文件工具、搜索、附件和沙箱必须使用同一个最终有效工作区。
- 不能出现侧栏显示项目 A，而命令实际运行在默认工作区的情况。

## 目录选择与安全

- 桌面端使用系统原生目录选择器。
- 浏览器端选择的是 Gateway 所在主机的目录，界面必须明确说明，不得伪装成浏览器用户电脑的目录。
- 后端必须确认路径存在、是目录且可访问。
- 路径在保存和授权前必须完成规范化，并处理目录链接带来的越界风险。
- 指定项目路径属于 owner 权限。
- 在读取项目指令、环境配置或执行项目自动化内容前，必须完成项目信任确认。
- 项目目录是任务的主工作目录；第一版不在项目编辑器中维护额外操作目录。
- 工作区外访问继续使用现有沙箱审批系统。启用自动审批模式时由现有机制自动处理，不为项目另建一套目录授权。
- 任何项目管理操作都不得删除磁盘上的项目目录。

## 空白草稿与持久化

- 空白任务草稿不作为正式任务保存。
- 项目工作区本身持久化，所以关闭并重新打开应用后，空项目仍显示“无任务”。
- 应用重新启动时默认仍不选中项目，不自动进入上次项目。
- 点击项目名称只展开或收起；点击已有任务打开任务，点击笔形按钮进入项目空白草稿。
- 重新选择已移除或已存在的项目目录时，不重复创建项目，而是恢复该项目并进入新的空白任务草稿。

## 旧数据整理

升级时自动整理已有任务：

- 使用 OpenSquilla 默认工作区的旧任务继续作为底部普通任务。
- 使用其他工作区路径的旧任务自动生成对应项目，并归入项目下面。
- 同一个规范化路径只生成一个项目。
- 整理过程只更新 OpenSquilla 元数据，不移动或修改任何磁盘文件。

## 实施范围

第一版包括：

- 独立项目工作区记录
- 选择项目和信任流程
- 项目空状态
- 项目信息、新建任务和更多菜单
- 置顶、编辑名称、删除任务历史和移除/恢复项目
- 项目任务与普通任务的侧栏布局和固定项目排序
- 项目草稿的首条消息原子创建
- 所有执行能力统一使用最终有效工作区
- 项目恢复与任务分支继承
- 旧任务自动整理

第一版不包括：

- 一个项目包含多个主目录
- 远程环境的多根目录映射
- 额外操作目录
- 项目拖动排序
- 在已有任务中切换项目
- 删除磁盘上的项目目录

## 错误处理

- 用户取消目录选择：不创建项目，也不改变当前页面。
- 目录无效或无权限：显示明确错误，不创建项目。
- 项目已经存在：直接选择已有项目并打开新的空白任务，不重复创建。
- 首条消息发送失败：保留输入内容和项目草稿，允许重试，但不留下空任务。
- 项目目录后来消失：保留侧栏项目记录并标记不可用，禁止执行，允许用户重新定位；不自动回退到默认工作区。
- 删除项目任务历史时，若当前正在查看被删除任务，完成删除后返回默认工作区的新任务草稿。

## 验收标准

- 未选择项目时，普通任务行为与现在一致。
- 选择项目后，项目立即显示，未发消息时显示“无任务”。
- 项目空白任务的第一条消息发送后，任务出现在正确项目下。
- 全局新建任务始终使用默认工作区。
- 项目中的新建任务始终使用该项目目录。
- 实际文件操作和命令执行目录与侧栏显示一致。
- 重启后项目列表保留，但主界面默认不选中项目。
- 项目名称只展开或收起，点击任务才切换工作区。
- 项目信息图标始终显示；新建任务和更多按钮只在项目行悬停或聚焦时显示。
- 置顶和未置顶项目保持固定顺序，不因任务活跃度移动。
- 普通任务平铺在所有项目分组下方。
- 移除并重新选择项目可以恢复原任务历史。
- 删除项目任务历史不会删除项目记录或磁盘文件。
- 已有非默认工作区任务在升级后自动归入对应项目。
- 无效路径、未授权用户和目录链接越界均被拒绝。
