# Sidebar Pinned, Projects, and Recents Design

## Goal

Present **Pinned**, **Projects**, and **Recents** as clear peer sections in the
sidebar. Each section shows only its own count, a pinned session appears only
in Pinned until it is unpinned, and hovering or focusing a session shows a
detail card with its optional project identity.

The change remains local to Web UI presentation, ordering, and browser-local
pin preferences. It does not change backend session or project ownership.

## Current behavior and root cause

`arrangeSidebarSections` already produces stable persisted-project groups:
project headers and their sessions come first, followed by sessions that are
not bound to a project. `SidebarConversations.vue` assigns every rendered row
to a project or Recents drag scope.

Three presentation limitations cause the reported behavior:

1. Projects is rendered in the main header, but Recents is generated by a CSS
   pseudo-element on the first ordinary session, so the headings do not read as
   peers.
2. The number beside Projects can be sourced from the total session count when
   there are no visible projects, so the label and number can describe
   different collections.
3. Pinning currently changes sort priority inside the existing ledger instead
   of projecting pinned sessions into one explicit top-level collection.

Session rows retain their workspace identity, but a row may have only a
`workspaceId` while the human-readable name lives on its project header. The
view projection must therefore resolve and carry the project header's title
when it extracts a project session into Pinned.

## Design

### Presentation projection

Build a pure view-layer projection from the existing arranged sidebar rows.
The projection produces three display zones without mutating the underlying
session or project records:

1. **Pinned**: every visible session with `pinned === true`, regardless of its
   original project, Recents, or supported session family.
2. **Projects**: persisted project headers and only their unpinned child
   sessions.
3. **Recents**: unpinned sessions that do not belong to a persisted project.

While walking each project block, the projection associates child sessions
with that project header and exposes a display-only project name. It never
replaces or rewrites the session's canonical `workspaceId`.

A pinned session is removed from its original rendered zone, so every session
has one sidebar location. Unpinning recomputes the projection from the unchanged
workspace fields and returns the session to its project or Recents.

Pinned is hidden when its count is zero. Projects and Recents retain their
existing empty-state behavior.

### Headings and counts

- Render Pinned, Projects, and Recents with the same heading typography,
  alignment, spacing, and real DOM structure.
- The Pinned count is the number of rendered pinned sessions.
- The Projects count is the number of rendered project workspace headers.
- The Recents count is the number of rendered unpinned, non-project sessions.
- Counts use the same filtered projection as the visible rows, so filtering
  cannot leave a heading count inconsistent with its contents.
- Keep project creation, search, and bulk-selection controls in the top header.
- Remove the first-recent-row CSS pseudo-heading and its compensating margin.

### Pinning and ordering

- The existing browser-local pinned-session key set remains the source of
  truth; no migration or backend write is introduced.
- Newly pinned sessions enter at the beginning of the global Pinned collection,
  following the existing manual session-order update.
- All pinned chat sessions share one drag scope, so they can be reordered across
  their original projects inside Pinned.
- Unpinned project sessions remain draggable only inside their own project.
- Unpinned non-project sessions remain draggable only inside Recents.
- Project pinning remains independent and continues to control project order.
- A pinned session keeps its original project fields; pinning never changes
  ownership.

### Session hover card

Hovering a session row with a mouse or focusing it with a keyboard opens a
non-interactive detail card beside the sidebar. The card contains:

- the complete session title;
- the existing localized relative-time representation of `updatedAt`;
- a folder icon and resolved project name only when the projection can match
  the session to project metadata.

For a session without a project, the card still shows title and time but omits
the project row. A pinned project session therefore continues to identify its
project even though it is rendered in Pinned.

Render the card through `Teleport` at the document root with fixed positioning.
Clamp it to the viewport and place it to the right of the hovered row when
space permits, so the sidebar's scroll container cannot clip it. Close it on
pointer leave, focus loss, scrolling, selection-mode changes, row menus, and
component teardown. The card does not capture pointer events or alter row
selection.

## Components and responsibilities

- `opensquilla-webui/src/components/SidebarConversations.vue`: derive and
  render the three display zones, maintain hover/focus card state and anchor
  position, and assign drag scopes without changing emitted pin events.
- `opensquilla-webui/src/components/SidebarSessionHoverCard.vue`: render the
  title, relative time, and optional project row as a focused presentational
  component.
- `opensquilla-webui/src/assets/base.css`: style peer headings, the global
  Pinned zone, and the hover card; remove the pseudo-heading workaround.
- `opensquilla-webui/src/styles/apple-modern.css`: align theme-specific sizing
  and spacing for all three headings if base styles are overridden.
- `opensquilla-webui/src/components/SidebarConversations.workspaces.test.ts`:
  verify projection, unique placement, counts, drag scopes, unpin return paths,
  and hover/focus behavior.
- `opensquilla-webui/src/components/SidebarSessionHoverCard.test.ts`: verify
  title/time rendering and conditional project identity.
- `opensquilla-webui/src/composables/useSessions.projects.test.ts`: retain
  arrangement coverage proving workspace ownership survives sorting.

## Error handling and compatibility

The feature adds no network calls, data migrations, or backend failure paths.
Existing localization keys for Projects, Recents, relative time, and project
labels are reused; a new Pinned heading key is added to every supported locale
only if no suitable shared key exists.

If project metadata is missing, the hover card omits the project row rather
than displaying a raw workspace ID or guessing from a filesystem path. If the
anchor disappears before the card is positioned, the card remains closed.
Touch-only devices keep the existing row interaction and do not require a
hover card.

## Verification

Use test-driven development:

1. Add failing tests for the three peer headings and independent counts.
2. Add failing tests proving a pinned project and non-project session appear
   exactly once in Pinned and return to their original zone when unpinned.
3. Add failing tests for one global pinned drag scope while preserving project
   and Recents drag boundaries for unpinned rows.
4. Add failing hover-card tests for title/time, project identity, absent project
   identity, keyboard focus, and viewport-safe Teleport rendering.
5. Implement the smallest projection, template, component, and style changes
   that satisfy those tests without changing backend ownership.
6. Run the focused component and composable tests, the full Web UI unit suite,
   type checking and architecture checks, and the production build.
